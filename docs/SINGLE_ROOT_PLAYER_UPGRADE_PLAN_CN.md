基线提交：`8df3723 Replace mixed lyric OSD with a single-root player`

相关历史：`bd0e067`（Theme V3 与音频律动）、`90f56a4`（Theme V4 参数化画布）

实施状态：Theme V5 账号权威同步与约束控制坞已于 2026-08-13 落地；真实服务器部署验收待执行。

适配目标：Emby Web `4.9.5.0`

## 0. 2026-08-13 Theme V5 实施记录

- 主题文档升级为 `schemaVersion: 5`、`fixed-canvas-v1`：横屏固定 `1920×1080`，竖屏固定 `1080×1920`；其他比例只做 contain 居中等比缩放，多余区域留空。V3/V4 与早期 V5 `anchored-canvas-v2` 继续兼容读取并一次性迁移。
- 正式画布只保留 `landscape` 与 `portrait`，且只包含 `artwork/metadata/lyrics/visualizer/controlDock` 五个图层。
- Workspace 成为账号唯一权威源；浏览器确认缓存、主题草稿和离线队列均按 `serverId + userId` 隔离。服务端草稿无条件作为当前账号的完整构图恢复，不再因其最初来源是内置预设而被刷新覆盖；PUT 只有收到递增 revision 才显示“账号已同步”。
- 非空 Workspace 永远优先于旧浏览器数据；只有全新且未迁移的账号会读取一次旧 `DisplayPreferences/localStorage`。
- 日常 500ms 防抖保存只写 Workspace，不再持续双写旧 DisplayPreferences。
- 控制坞随主题分别保存横竖屏的行、分组、按钮顺序、显隐、对齐、间距和换行；进度与播放按钮不可删除。
- 自动化已覆盖服务器 Workspace 胜出、初始化前零保存、账号/服务器缓存隔离、横竖 profile 共存、500ms PUT 与 revision 冲突副本。
- 本地 C# 严格编译、真实 Emby 4.9.1.90 API 合同、Theme V5/单根运行时测试已通过；POSIX 安装器测试需在 Linux/Docker 主机执行。
- 插件版本为 `0.5.0`，前端构建 ID 为 `2026.08.13-theme-v5-fixed-canvas-sync-r2`。服务端图层坐标范围已扩大，需重装 DLL 并重启 Emby。

## 1. 结论与升级原则

本轮不推翻 `8df3723` 的单根播放器架构，也不恢复 V3 的混合 DOM Hook。升级以单根播放器为唯一运行路径，在此基础上完整继承并修正 V3 的频谱分析能力、Theme V4 的参数化能力，以及媒体信息、播放列表、设置和设计器的主题化弹层体验。

实施顺序必须是：

1. 先保证服务器四个文件、浏览器缓存和运行时模块属于同一构建。
2. 再建立 V3 → V4 → 单根播放器的能力继承契约。
3. 然后重做音频采样与视觉频域映射。
4. 统一改造媒体信息、播放列表、设置和设计器弹层。
5. 最后校准九套主题的 18 个横竖屏构图并做真实浏览器验收。

禁止继续通过新增高优先级 `z-index`、复制原生 DOM、模拟点击隐藏按钮或为单套主题追加临时坐标来解决问题。

## 2. 已核实的现状

### 2.1 Git 历史中的能力关系

| 提交 | 主要能力 | 当前处理方式 |
|---|---|---|
| `bd0e067` | 对数频带、AGC、频谱倾斜、`centerOut/lowToHigh/radial`、Theme V3 | 保留能力目标，修正采样与布局缺陷，不复制旧 DOM 架构 |
| `90f56a4` | Theme V4、anchored canvas、九套主题、横竖屏布局、JSON 导入导出 | 继续作为唯一主题数据和渲染体系 |
| `8df3723` | VideoOsd 生命周期、单根播放器、PlaybackBridge、自有歌词与队列、四文件安装回滚 | 继续作为运行架构基线 |

V3 的频谱能力没有全部消失，但 `8df3723` 仍保留以下缺陷：

- FFT 为 `2048`，48 kHz 下低频 bin 间隔约 23.4 Hz，第一批可听八度的分辨率不足。
- 对数频带边界最终落到整数 bin；窄频带会重复读取同一 bin，视觉上看似有很多柱，实际包含重复数据。
- 音乐能量集中在低频和中低频时，传统从左到右排列会造成只有左侧明显运动。
- 旧版 `centerOut` 和 `radial` 不能证明每个视觉采样点都有严格对称的频域对应点。
- 切换频率布局后，旧能量、峰值和原始频带缓存可能短暂污染新布局。

### 2.2 当前服务器的真实运行状态

2026-08-13 在 1280×720 的真实播放会话中检查到：

- 页面存在 `body.elyric-player-active-page` 和 Theme V4 数据属性。
- 可见播放器是 `body` 直属的 `.elyric-player-shell.elyric-theme-picker`。
- 该播放器为 `position:fixed; z-index:1260`。
- 页面不存在 `.elyric-player-root`。
- 原生 OSD 与旧播放器节点同时存在于可访问树中。

而 `8df3723` 的本地代码明确要求：

```text
.elyric-player-root
├── background
├── stage
├── queue
├── settings
├── media-card
└── overlay-scrim
```

因此当前“界面全乱”的第一原因不是某一套主题坐标，而是浏览器仍运行旧混合播放器模块，或服务器的 `videoosd.js/css`、`lyrics.js/css` 没有形成同一构建。九套主题的视觉调整必须等部署完整性通过后再验收，否则所有截图和结论都不可信。

### 2.3 弹层现状

- 媒体信息已有按钮锚定逻辑，但设置仍可能退化为横屏 `46vw × 100dvh` 全高侧栏。
- 播放列表以固定位置为主，没有与媒体卡共享同一锚定定位器。
- 设置、媒体信息和部分遮罩仍可能挂到 `body`，破坏单根 DOM 合约。
- 三类弹层的背景、边框、阴影、圆角、透明度和模糊没有统一从当前主题 token 读取。
- 隐藏弹层在定位前无法取得真实内容高度，容易直接使用视口比例上限，导致短内容也显示成大面板。
- 内容异步变化、窗口缩放、横竖屏变化后并非全部弹层都会重新定位。

## 3. 目标架构

### 3.1 单根播放器是唯一可见运行路径

```text
VideoOsd lifecycle
  → PlaybackBridge
  → PlayerRuntime
      ├── ThemeRuntime
      ├── LyricRepository + LyricViewport
      ├── QueueRepository + QueueView
      ├── AudioAnalysisEngine + VisualizerRenderer
      └── OverlayManager
          ├── MediaInformationOverlay
          ├── QueueOverlay
          ├── SettingsOverlay
          └── ThemeDesignerOverlay
```

硬性约束：

- 所有可见播放器元素必须是 `.elyric-player-root` 的后代。
- `lyrics.js/css` 保持 Emby 原版，不再 Hook `LyricsRenderer`。
- 播放器只通过 PlaybackBridge 调用 Emby 正式模块，不复制第二套播放状态机。
- 自定义根节点成功完成关键模块、DOM 和主题初始化后，才隐藏原生 OSD。
- 初始化、主题迁移或运行时关键步骤失败时，销毁自定义根节点并完整恢复原生 OSD。
- 保留 `?elyric=off` 会话级故障开关。

### 3.2 建立能力继承清单

每项历史能力必须有唯一的“来源、运行实现、主题字段、自动化测试和视觉验收”对应关系。禁止仅凭代码中存在相同变量名判断已经继承。

| 能力 | 运行实现 | 主题数据 | 自动化验收 |
|---|---|---|---|
| 对数 FFT 频带 | `AudioAnalysisEngine` | `visualizer.analysis` | 固定频率夹具 |
| 三种频率布局 | `FrequencyLayoutMapper` | `visualizer.frequencyLayout` | 左右/环形对称断言 |
| AGC、噪声门、频谱倾斜 | 分析层 | `visualizer.analysis` | 静音、低音、全频夹具 |
| 九套横竖屏构图 | `ThemeRuntime` | Theme V4 layouts | 9×6 尺寸截图矩阵 |
| 用户主题和导入导出 | Theme V4 normalizer | JSON V4 | 往返与迁移测试 |
| 弹层主题化 | `OverlayManager` | `overlays` 可选字段 | DOM、定位和视觉测试 |

## 4. 第一阶段：部署完整性与缓存治理

这是发布阻断阶段。没有通过本阶段，不进入主题视觉验收。

### 4.1 四文件构建清单

安装包生成构建清单：

```json
{
  "embyVersion": "4.9.5.0",
  "buildId": "2026.xx.xx-single-root-vNext",
  "files": {
    "videoosd.js": "sha256",
    "videoosd.css": "sha256",
    "lyrics.js": "sha256",
    "lyrics.css": "sha256"
  }
}
```

安装器必须：

- 从已验证的四份 Emby 原文件生成目标文件。
- 验证 `videoosd.js` 含 VideoOsd 生命周期 Hook 和 `.elyric-player-root` 标记。
- 验证 `lyrics.js` 不含 `LyricsRenderer.prototype` Hook。
- 验证 JS 与 CSS 的构建 ID 完全一致。
- 四文件先写临时文件，再成组原子替换；任一失败全部回滚。
- 安装结束输出活动文件 SHA-256、构建 ID和“需要完整刷新浏览器”的明确提示。
- 重复安装同一构建必须幂等。

### 4.2 运行时自检

自定义根节点添加：

```html
<div class="elyric-player-root"
     data-elyric-build="2026.xx.xx-single-root-vNext"
     data-elyric-schema="4">
</div>
```

运行时检查：

- 页面同时存在旧 `.elyric-player-shell:not(.elyric-player-root)` 时，拒绝挂载并恢复原生 OSD。
- JS 与 CSS 构建标记不一致时，拒绝挂载并在控制台输出单条可诊断错误。
- 同一个 VideoOsd 实例最多存在一个自定义根节点。
- 页面离开、重入和热更新后清理遗留 `body` 属性和旧根节点。
- 调试面板可复制构建 ID、四文件状态、当前主题 ID、布局 profile 和能力状态，但不包含令牌或用户隐私数据。

### 4.3 缓存验收

- 冷启动新浏览器会话后确认 `.elyric-player-root === 1`。
- 完整刷新后仍只能存在一个根节点。
- 从旧混合版本升级时不得同时出现旧 shell 和新 root。
- 浏览器仍持有旧 AMD 模块时，显示“前端已更新，请完整刷新”并保持原生 OSD，而不是展示半套自定义界面。

## 5. 第二阶段：Theme V4 兼容与九套主题基线

### 5.1 数据策略

- Theme V4 和 `anchored-canvas-v1` 继续作为唯一主题格式。
- 不删除用户主题，不修改已有主题 ID，不让内置主题覆盖用户主题。
- V1–V3 只在读取时迁移为标准 V4；保存和导出统一使用标准 V4。
- 旧主题缺少的新字段使用 baseTheme 默认值，不把 `undefined` 直接转换为 0、空颜色或隐藏状态。
- 导入 JSON 不接受用户 ID、服务器路径、revision 和私有资产真实路径。
- 迁移失败只隔离损坏主题，不能阻止播放器使用安全内置主题启动。

### 5.2 布局策略

- 正式布局只保留 `landscape` 和 `portrait`。
- 横屏小设备运行时进入 compact，不产生第三份用户布局。
- 2560×1440 是最大设计画布；3840×2160 居中展示设计画布，背景和底部控制台铺满屏幕。
- 专辑图、歌曲信息、歌词、频谱、进度、控制、音量和辅助按钮全部绑定自有 stage 图层。
- 每个图层只允许一套几何来源，禁止 V3 旧 CSS、V4 CSS 变量和运行时内联坐标同时控制同一属性。
- 底部控制台保留安全锚点，退出、设置和主要播放控制永远可达。

### 5.3 九套主题复校

九套主题各校准 landscape/portrait 两版，形成 18 个标准 fixture：

1. 编辑唱片
2. Spotify 海报
3. 移动唱机
4. 薄荷拟物
5. 实体唱盘
6. 专辑列表
7. 封面流
8. 唱片歌词
9. 粉色拟态

每套都必须检查：

- 封面与歌曲信息的视觉重心是否平衡。
- 歌词是否为主阅读区域且不被频谱遮挡。
- 2560×1440 和 3840×2160 是否产生失衡的大面积空白。
- 竖屏是否保持封面、信息、歌词的清晰纵向层级。
- 横屏手机是否隐藏次要控件并保持主要控制可达。
- 用户从内置主题另存为自定义主题后，横竖屏参数是否完整保留。

## 6. 第三阶段：音频律动统一重构

### 6.1 分析层

保留对当前媒体 `captureStream()` 的直接分析；无法建立实时音频源时才进入明确标记的节奏估算模式。

默认参数：

- `fftSize = 4096`，48 kHz 下 bin 间隔约 11.7 Hz。
- 分析范围约 30 Hz–16 kHz，并限制在 Nyquist 内。
- 频带边界按真实 Hz 与对数刻度计算。
- 每个视觉频带使用分数 FFT bin overlap 加权，不重复整数 bin。
- 频带能量混合加权平均和局部峰值。
- 使用慢速 AGC；增益下降快于上升，避免弱段突然放大噪声。
- 加入可调噪声门、频谱倾斜补偿和低频增强。
- 额外输出 RMS、peak、low、mid、high 和 spectral flux。
- 波形使用慢速 AGC，禁止逐帧归一化成固定振幅。
- 暂停、静音和真正静音时自然衰减到零，不伪造高频运动。

必须防止：

- 同一个媒体元素被重复连接到 AudioContext。
- 切歌后沿用上一首的能量、峰值或 AGC 状态。
- 页面退出后遗留 AudioNode、动画帧或事件监听器。
- 实时分析失败时静默显示一套看似真实但与音乐无关的随机动画。

### 6.2 频率布局

`frequencyLayout` 是独立参数：

- `centerOut`：默认。低频位于中心，频率向两侧升高；每个点与另一侧严格镜像。
- `lowToHigh`：对数频率从左到右，供传统分析仪使用。
- `radial`：同一频段在圆环相对两侧出现，低频不能只驱动一个孤立圆弧。

展示规则：

- 柱状、峰值回落、镜像线条和粒子默认使用 `centerOut`。
- 波形横轴表示时间采样，覆盖完整宽度，不使用频率布局。
- 折线和流线使用对数频带并覆盖完整画布。
- 呼吸效果由低频包络控制基础半径，spectral flux 控制瞬态扩张。
- 切换布局时清空能量、峰值和原始频带缓存。

### 6.3 主题参数

以下参数全部进入主题 JSON，并由服务端和前端使用同一范围校验：

```json
{
  "visualizer": {
    "style": "bars",
    "frequencyLayout": "centerOut",
    "analysis": {
      "minFrequency": 30,
      "maxFrequency": 16000,
      "sensitivity": 1,
      "response": 0.7,
      "smoothing": 0.72,
      "density": 48,
      "bassBoost": 1,
      "noiseGate": 0.018
    }
  }
}
```

### 6.4 频谱自动化测试

用确定性输入夹具验证：

- 60 Hz 低音
- 250 Hz 中低频
- 1 kHz 人声主体
- 8 kHz 高频打击
- 低音 + 高频双音
- 全频音乐
- 静音、暂停和静音后恢复

验收断言：

- `centerOut` 全部镜像点误差小于规定容差。
- `lowToHigh` 的峰值区域与输入频率一致。
- `radial` 相对两侧使用同一频带。
- 纯低音不能只让左侧运动。
- 高频输入不能错误出现在低频中心。
- 静音后在规定时间内衰减到视觉静止。

## 7. 第四阶段：统一主题弹层系统

### 7.1 OverlayManager

媒体信息、播放列表、设置和主题设计器统一交给 `OverlayManager`：

```text
open(type, trigger, options)
close(type, reason)
closeTop(reason)
reposition(type)
measure(type)
syncTheme(theme)
destroy()
```

能力要求：

- 同一时刻只打开一个主要弹层。
- 所有弹层、箭头和遮罩都位于 `.elyric-player-root`。
- Escape、返回键、点击遮罩和关闭按钮行为一致。
- 打开时锁定焦点，关闭后把焦点还给触发按钮。
- 窗口缩放、visualViewport 变化、横竖屏切换和异步内容变化后重新定位。
- `prefers-reduced-motion` 下使用近乎即时的透明度切换。

### 7.2 按钮锚定定位

landscape 使用统一定位算法：

1. 读取触发按钮 `getBoundingClientRect()`。
2. 读取 visualViewport 安全矩形和安全边距。
3. 在不可见但可测量状态下计算弹层真实内容尺寸。
4. 优先选择按钮上方；空间不足时选择下方。
5. 水平位置以按钮中心为锚点，并限制在视口安全边距内。
6. 高度取“内容高度、主题/用户上限、该方向可用空间”的最小值。
7. 箭头尖端指向触发按钮，并在靠近边缘时独立调整，不能把整个面板推离屏幕。

portrait 使用底部安全抽屉，不显示误导性的按钮箭头。

默认尺寸目标：

| 弹层 | Landscape 宽度 | 最大高度 | Portrait |
|---|---:|---:|---|
| 媒体信息 | 360–500 px | 72dvh | 最大 76dvh 的安全抽屉 |
| 播放列表 | 360–440 px | 66dvh | 最大 76dvh 的安全抽屉 |
| 设置 | 420–540 px | 72dvh | 最大 82dvh 的安全抽屉 |
| 主题设计器 | 根据编辑任务单独布局 | 82dvh | 全宽安全工作区 |

短内容必须收缩到内容高度，不允许仅因为上限是 72dvh 就直接占用 72dvh。

### 7.3 主题视觉 token

Theme V4 增加可选 `overlays` 外观字段；旧主题缺失时由当前 baseTheme 生成安全默认值：

```json
{
  "overlays": {
    "surface": "floating",
    "background": "#121722",
    "foreground": "#ffffff",
    "borderColor": "rgba(255,255,255,.14)",
    "radius": 22,
    "opacity": 0.94,
    "backdropBlur": 24,
    "shadow": "soft",
    "scrimOpacity": 0.16,
    "animation": "anchored-scale"
  }
}
```

各弹层允许覆盖自己的宽度和最大高度，但共享：

- 背景取色
- 前景色与次级文字色
- 边框和高光
- 圆角
- 透明度
- 高斯模糊与饱和度
- 阴影
- 遮罩强度
- 动画风格

媒体信息仍可使用主题定义的独立 surface；不能硬编码为与所有主题相同的黑色玻璃卡。

### 7.4 动画

landscape 弹层从按钮锚点出现：

- 打开：180–220 ms，透明度 0→1、位移 8–12 px→0、缩放 0.965→1。
- 关闭：140–180 ms，反向位移和透明度退出。
- `transform-origin` 使用箭头尖端位置。
- 内容加载完成导致尺寸变化时使用轻微尺寸过渡，不重新播放整段入场动画。
- 遮罩只做轻微暗化和约 2 px 模糊，不能吞掉播放器主题背景。

动画结束后清理 Web Animations fill 状态，防止后续 CSS transform 被旧动画覆盖。

### 7.5 各弹层专项要求

媒体信息：

- 用户可配置显示歌曲概览、文件、音频、图像和歌词流。
- 内容异步加载后重新测量和定位。
- 路径等长文本可换行或横向安全截断，不能撑出卡片。

播放列表：

- 显示当前项和下一首，支持点播、移除和拖动排序。
- 长队列只滚动 body，标题和关闭按钮固定。
- 更新、移除或排序后保持当前滚动位置并重新检查高度。

设置：

- 标题和关闭按钮固定，正文独立滚动。
- 普通设置使用紧凑弹层；只有进入画布设计器时才切换专门工作区。
- 不把 400 余项参数一次性展开，按背景、布局、封面、信息、歌词、频谱、控制台和弹层分组渐进展开。

## 8. 第五阶段：CSS 与运行时债务清理

当前 CSS 中同一弹层选择器在多个历史阶段重复声明，`z-index`、宽高和定位存在多层覆盖。升级时必须：

- 建立唯一层级 token，例如 background、stage、console、scrim、overlay、designer、toast。
- 删除旧 V3 body 弹层、旧设置全高侧栏和仅媒体卡使用的独立定位规则。
- 每个关键选择器只保留一个正式布局块和必要的响应式覆盖。
- 不使用 `214748xxxx` 作为修复层级冲突的常规手段。
- 把播放器 CSS 依职责分段生成，并在最终适配器中保留清晰的构建边界注释。
- 为禁止选择器建立静态测试：原生歌词、原生队列、原生播放按钮和旧 body shell 选择器不得重新进入单根运行路径。

### 9.3 真实服务器发布闸门

发布必须按以下顺序：

1. 本地完整验证通过。
2. 在干净模拟目录验证四文件安装、回滚和卸载。
3. 部署测试服务器并记录活动四文件 hash。
4. 新浏览器会话确认运行时 build ID 与服务器一致。
5. 确认旧 shell 为 0、新 root 为 1。
6. 用真实歌曲检查歌词、队列、媒体信息、设置和实时频谱。
7. 完成六种尺寸和九套主题抽查后再推正式版本。

任何一步失败都恢复 Emby 原生 OSD；不能带着半套自定义界面继续发布。
